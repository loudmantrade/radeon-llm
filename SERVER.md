# Qwen3 на Radeon для OpenCode

Сервер: `llama-server`, Qwen3-4B-Instruct-2507 Q4_K_M, Vulkan / MoltenVK 1.4.2.

- API: `http://127.0.0.1:8080/v1`
- Модель API: `qwen3-4b-local`
- OpenCode model ID: `radeon/qwen3-4b-local`
- Контекст: 8192 токена, один одновременный запрос, ответ до 1024 токенов по умолчанию.
- Авторизация: Bearer API key из `server/api-key`, файл создан с правами 0600.
- HTTP: `/health`, `/v1/models`, `/v1/chat/completions`, SSE streaming и function calling.

## Установка и запуск

В обычном macOS Terminal, без sudo:

```bash
cd /path/to/radeon-llm
./daemon.command install
./check-api.command
```

`install` копирует runtime, модель и библиотеки в `~/Library/Application Support/radeon-llm` (примерно 2,6 ГБ), затем копирует подготовленный plist в `~/Library/LaunchAgents/local.radeon-llm.qwen3.plist`, включает запуск после входа пользователя и запускает сервис. LaunchAgent перезапускает сервер при аварийном завершении. Скрипт ждёт готовности API до 180 секунд. Если загрузка длится дольше, проверь `status` и `logs`.

После установки остановленный сервис можно снова запустить:

```bash
./daemon.command start
```

Управление:

```bash
./daemon.command status
./daemon.command restart
./daemon.command stop
./daemon.command logs
./daemon.command uninstall
```

`stop` останавливает сервис до следующего `start` или входа пользователя, если автозапуск установлен. `uninstall` также удаляет plist автозапуска; модель и проект сохраняются.

Если LaunchAgent не запускается, проверь `logs/server.stderr.log`. Для проверки сервера в foreground:

```bash
./daemon.command run
```

Это запускает тот же GPU-сервер до Ctrl+C. В другом окне Terminal можно выполнить `./check-api.command`.

## OpenCode

В каталоге нужного репозитория запусти:

```bash
/path/to/radeon-llm/opencode-radeon.command
```

Можно передать путь к репозиторию аргументом launcher. Launcher сохраняет текущий рабочий каталог, задаёт `OPENCODE_CONFIG` и запускает OpenCode 2 с `--standalone`, чтобы приватный процесс видел настройки. Модель `radeon/qwen3-4b-local` выбрана полем `model` в конфигурации, без неподдерживаемого корневого флага `--model`. OpenCode должен быть установлен и доступен как `opencode` в PATH.

Готовый конфиг: `opencode.json`. Для OpenCode 2 он использует `providers` / `package` / `settings` и пакет `@opencode/ai/providers/openai-compatible`, правильный `/v1` baseURL и считывает локальный ключ через `{file:...}`. Как основная, так и малая модель направлены на локальный сервер. Настройки других проектов OpenCode могут переопределять поля этого конфига согласно правилам приоритета OpenCode.

Функции, переданные в API-запросе, возвращаются клиенту как `tool_calls`. Их выполняет OpenCode; встроенные инструменты llama-server не включены.

8192 токена включают инструкции, описания инструментов, историю и ответ. Конфиг сообщает OpenCode этот лимит и включает автоматическое сжатие истории. Длинные инструкции проекта или большие результаты инструментов могут не поместиться: эта конфигурация предназначена для небольших задач. 4B-модель имеет ограниченные способности к сложному автономному программированию.

## Конфигурация и логи

Настройки сервера: `server/config.json`. После изменения параметров повтори `./daemon.command install`, чтобы обновить runtime. При изменении контекста или порта обнови соответствующие лимиты/baseURL в `opencode.json`. Параметр `fit_margin_mib: 256` оставляет запас VRAM; llama.cpp может подогнать размещение под доступную память. Фактическое число GPU-слоёв и размер контекста видны в логе. Конфигурация GPU с 8192 токенами подтверждена после переноса runtime; результаты приведены ниже.

- `logs/server.stdout.log` / `logs/server.stderr.log`: демон.
- `logs/api-check-8080.json`: успешная проверка API на Radeon.
- `logs/api-check-18080.json`: проведённая проверка API на CPU.
- `logs/server-cpu-test.log`: проверенный сервер на CPU, тестовый порт 18080.

Не запускай одновременно отдельную GPU-генерацию и демон: они будут конкурировать за 4 ГБ видеопамяти.

Пересборка:

```bash
./build-server.command
```

## Выполненная проверка

Собран реальный `llama-server`. Foreground CPU-сервер с Qwen3 и контекстом 2048 прошёл:

1. Health и корректный alias в `/v1/models`.
2. Отклонение запроса к модели без Bearer key.
3. Обычный `/v1/chat/completions`, ответ `4` на `2 + 2`.
4. Потоковый вызов функции `add`: SSE, JSON-аргументы `{a:2,b:2}`, `finish_reason: tool_calls` и маркер `[DONE]`.
5. Возврат результата функции в диалог и итоговый ответ `4`.

Временный CPU-сервер после проверки остановлен. Shell-скрипты, Python, JSON и LaunchAgent plist проверены. `launchctl bootstrap` из среды Codex вернул код 5; daemon не запущен. GPU-демон и OpenCode клиент целиком пока не проверены: OpenCode в PATH среды Codex отсутствует. Запуск из обычного Terminal нужен для окончательной проверки.

Документация интеграции: https://docs.opencode.ai/docs/providers/ и https://dev.opencode.ai/docs/config

## Исправление запуска из Documents

Первый пользовательский запуск LaunchAgent завершался кодом 2: macOS запрещала чтение `daemon.py` из Documents (`Operation not permitted`). Установщик изменён: теперь все необходимые файлы копируются в Application Support, нативные библиотеки используют соседние dylib вместо путей сборки в Documents, а логи пишутся в runtime/logs. Ключ копируется без изменения, поэтому конфигурация OpenCode остаётся применимой. `daemon logs` читает реальные пути логов из установленного plist. При аварии запуска менеджер показывает последние строки stderr и останавливает цикл перезапусков вместо ожидания 180 секунд.

## Подтверждённый запуск после переноса

LaunchAgent запущен из `~/Library/Application Support/radeon-llm`, API на порту 8080 готов. В GPU-логе подтверждены 37/37 слоёв, контекст 8192, веса 2375,91 МиБ и KV-кэш 1152 МиБ. Файл `logs/api-check-8080.json` подтверждает успешные health, авторизацию, модель, обычный ответ, потоковый вызов функции и возврат результата функции. Доступ к защищённой папке Documents для работы демона больше не требуется. Сам клиент OpenCode пока не проверялся.

## Совместимость с OpenCode 2.1.4

Launcher исправлен под установленный клиент: корневой `--model` удалён, модель задаётся конфигурацией; `run` получает `--standalone` после имени подкоманды. При отсутствии OpenCode в PATH используется `~/.opencode/bin/opencode`. Формат провайдера переведён на V2. Клиент распознал локальную конфигурацию и направил запрос к Radeon API. Для проверки в среде Codex использовались изолированные XDG-каталоги в work/, отключённый watcher только в окружении теста и закрытый stdin.

Проверка OpenCode 2.1.4 завершена успешно: реальный `run --standalone` через новый launcher получил ответ `4`, stderr пуст, exit code 0. Отчёт: `logs/opencode-v2-smoke.json`. Входной контекст OpenCode составлял 5197 токенов, поэтому первый запрос потребовал нескольких минут; обычные короткие curl-запросы не отражают этот расход. Пользовательские XDG-каталоги и настройки для теста не менялись.

## Компактный агент для окна 8192

Агент `radeon` теперь выбран по умолчанию для новых чатов. Он использует короткую системную инструкцию и локальные coding-инструменты; web, subagent, skill, task-list и plan-переходы для него отключены. Инструкция просит читать не более 80 строк за раз, ограничивать shell-вывод и выполнять одну небольшую задачу. Стандартный Build остаётся доступен. Исходный конфиг сохранён в `opencode.before-compact.json`.

Установлены `compaction.keep.tokens=1024` и `compaction.buffer=1536` для небольшого окна. Сжатие потерь не исключает; сохранение точного содержимого старых участков истории не гарантируется. Сам размер окна остался 8192. При 16384 текущий FP16 KV-кэш потребовал бы 2304 МиБ вместо 1152; вместе с весами 2375,91 МиБ это уже больше 4 ГБ до вычислительных буферов. Увеличение требует отдельной проверки квантования KV/другой модели или частичного переноса на CPU.

Реальный тест OpenCode с агентом `radeon` получил правильный ответ `4`, exit code 0. Входной промпт: 3361 токен против прежних 5197, снижение на 1836 токенов (35,3%). Prefill в двух одиночных прогонах: 85,28 с против 119,90 с; сравнение не является строгим бенчмарком. Лог-сводка: `logs/compact-agent-check.json`. Серверные параметры и кэш не менялись; перезапуск демона не требуется.

Чтобы применить профиль к работе, перезапусти launcher и создай новый чат с агентом `radeon`. Старый чат может сохранять выбранный Build и прежнюю историю.

## KV-кэш на диске

Реализовано сохранение последнего контекста между перезапусками. Включение с проверкой на Radeon: `./enable-kv-cache.command`. Обновляются только скрипты и конфигурация; установленная нативная сборка сохраняется. Инструкция и ограничения: [PERSISTENT-KV.md](PERSISTENT-KV.md). Основной контекст остаётся 8k.

## Профиль KV Q8

Подготовлен профиль 8k/Q8_0 для ключей и значений с проверенной FA-only сборкой. Для установки с резервной копией, API-проверками и проверкой восстановления после перезапуска используйте `./enable-q8.command`. [Инструкция и откат](Q8-DAEMON.md). Изменение исходного config.json само по себе ещё не меняет установленный демон.

## Переход с 8k на 16k

Текущая целевая конфигурация проекта — 16384 токена с KV Q8. Установленный демон меняется после `./enable-16k.command`; OpenCode limit и тайм-аут обновляются после проверок. [Инструкция 16k и откат](DAEMON-16K.md).

## Несколько KV-контекстов

Подготовлен индексированный кэш с точным поиском префикса, счётчиками обращений, очисткой и горячими mmap. Включение с проверкой: `./enable-indexed-cache.command`; статус: `./cache-status.command`. [Устройство, лимиты и откат](INDEXED-CACHE.md).
