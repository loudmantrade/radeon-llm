# Сборка и установка одной командой

Скачайте исходники (или клонируйте репозиторий), откройте терминал в его папке:

```bash
# macOS, Intel или Apple Silicon
./setup.command
```

```powershell
# Windows 10/11 x64
.\setup.ps1
```

Если Python 3.11+ уже установлен, одинаковый вход для обеих ОС:

```console
python setup.py
```

`setup.command` и `setup.ps1` ищут подходящий Python. Если его нет, они могут
установить Python через уже установленный Homebrew или winget соответственно.
Сам менеджер пакетов автоматически не устанавливается. Если политика Windows
запрещает выполнение `.ps1`, используйте `python setup.py`; менять политику
PowerShell для этого не требуется.

## Что выполняет setup

1. Определяет ОС/архитектуру, проверяет Git, CMake и компилятор.
2. Устанавливает недостающие зависимости через Homebrew/winget, когда они доступны.
3. Получает закреплённую ревизию llama.cpp, применяет патч проекта и собирает
   `llama-server` именно на текущей машине. Готовые EXE с другой ОС не используются.
4. Скачивает стандартную Qwen3-4B-Instruct-2507 Q4_K_M, проверяет размер и SHA-256.
   Существующий корректный GGUF не скачивается повторно.
5. Создаёт локальный ключ/конфиг при необходимости, сохраняет существующий ключ и
   пользовательские параметры. Перед изменением существующего конфига создаётся
   `config.before-setup-*.json`. Управляемые поля backend, путь новой сборки и
   интерпретатор обновляются; `--context` меняет размер окна явно.
6. Регистрирует пользовательский автозапуск, запускает демон и проверяет API,
   авторизацию, chat, потоковый tool call и возврат результата инструмента.

Сборка и загрузка модели заканчиваются до остановки уже установленного демона.
Этап установки обновляет его файлы и перезапускает процесс; не запускайте полную
установку во время важной генерации. Логи сохраняются в `logs/sessions/setup-*.log`,
указатель на последний запуск — `logs/latest-setup.json`.

Потребуется несколько гигабайт диска под модель, исходники, сборку и SDK.
OpenCode устанавливается отдельно; setup подготавливает его провайдер, но не
заменяет пользовательскую установку OpenCode.

## macOS

- Intel: Vulkan, SDK LunarG 1.3.296.0 и MoltenVK 1.4.2. Эти зависимости скачиваются
  в папку проекта из официальных источников с проверкой закреплённых SHA-256.
  Устанавливается только SDK core, без системного Vulkan SDK.
- Apple Silicon: Metal, встроенные шейдеры. Для этого варианта Vulkan SDK/MoltenVK
  не нужны. Принудительный Vulkan доступен через `--backend vulkan`.
- Нужны Xcode Command Line Tools. Если их нет, setup открывает штатную установку
  `xcode-select --install` и останавливается: завершите диалог и повторите команду.
- Если нет Python/CMake и Homebrew, установите Python с python.org и CMake с
  cmake.org либо Homebrew с brew.sh и повторите запуск.
- LaunchAgent работает в пользовательской GUI-сессии. На headless/SSH-системе
  без входа пользователя регистрация `gui/<uid>` может быть недоступна.

Рабочая копия демона, модель и ключ размещаются в
`~/Library/Application Support/radeon-llm`, LaunchAgent — в `~/Library/LaunchAgents`.
Используется выбранный setup интерпретатор, а не жёстко заданный `/usr/bin/python3`.
После изменения rpath собранные Mach-O файлы подписываются ad-hoc — это необходимо
для загрузки перенесённых библиотек на Apple Silicon.

```bash
./daemon.command status
./daemon.command logs
./daemon.command stop
./daemon.command uninstall
```

## Windows

Используется нативный Vulkan, без MoltenVK. Если инструменты отсутствуют, setup
вызывает winget для Git, CMake, Visual Studio 2022 Build Tools с C++ workload и
Khronos Vulkan SDK. Установка может показывать UAC и лицензионные диалоги.
Если инструмент требует перезагрузки или ещё не появился на PATH, setup сообщает
об этом: завершите установку/перезагрузку и повторите команду.
При уже установленных Build Tools убедитесь, что выбран C++ workload.

Создаётся задача `RadeonLLM` при входе текущего пользователя; конфиг, ключ и KV
хранятся в `%LOCALAPPDATA%\radeon-llm`. EXE/DLL копируются в `native` внутри этого
runtime. Сборка идёт отдельно, в `llama.cpp/build-setup-vulkan`, чтобы работающий
сервер не блокировал линковку EXE/DLL при обновлении. Затем setup останавливает
старый процесс, копирует новую сборку и запускает её заново.
Задача ссылается на текущую папку репозитория
и Python: не удаляйте их после установки; после переноса повторите setup.
Администратор нужен только установщикам зависимостей, если они его запрашивают;
сам демон выполняется от обычного пользователя.

```powershell
python server/windows.py status
python server/windows.py logs
python server/windows.py stop
python server/windows.py uninstall
```

Нужен работающий Vulkan-драйвер видеокарты. Setup не меняет настройки GPU и не
устанавливает драйвер производителя. Если сборка успешна, но GPU недоступен,
смотрите журнал и вывод `llama-server --list-devices`.
[Подробности Windows](WINDOWS.md).

## Управление установкой

Параметры одинаковы для обоих скриптов и `python setup.py`:

```console
python setup.py --plan
python setup.py --check
python setup.py --build-only --no-deps
python setup.py --context 8192 --jobs 4
python setup.py --backend vulkan
```

- `--plan`: показать выбранную ОС, backend и план без изменения службы/конфига.
  Обёртка всё равно сохраняет журнал запуска.
- `--check`: только проверить зависимости, без установки; код выхода 1 означает,
  что чего-то не хватает.
- `--build-only`: собрать движок, без модели, конфигурации и службы. Зависимости
  при необходимости ещё могут устанавливаться.
- `--no-deps`: запрещает установку зависимостей; при отсутствии чего-либо выдаётся
  ошибка. Удобно для CI и заранее подготовленных машин.
- `--context`: задать окно, например 8192 для небольшой VRAM; по умолчанию
  сохраняется существующее значение или используется профиль 16384.
- `--jobs`: число параллельных задач сборки (по умолчанию до 6).

Setup не сбрасывает чужую ревизию/изменения в `llama.cpp` и не удаляет кеши.
При незавершённой установке SDK каталог нужно сначала проверить по журналу;
скрипт не стирает его автоматически. Файлы конфигурации, резервные копии, веса,
SDK, ключи и журналы исключены из Git.
