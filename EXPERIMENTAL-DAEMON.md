# Экспериментальный перенос KV-фрагментов в демоне

Включение:

```bash
/path/to/radeon-llm/enable-experimental-reuse.command
```

Профиль сохраняет контекст 16k, Q8 K/V, индексированный дисковый кэш и публичный API OpenCode. Используется изолированная сборка `experimental/shift-active/bin` с `LLAMA_KV_SHIFT_ACTIVE_ONLY=1`; native server запускается с `--cache-reuse 64`. Совпадающие фрагменты длиной от 64 токенов могут переиспользоваться после удаления части прежнего текста. Поддержка произвольной замены/перестановки фрагментов не добавляется; это поведение штатного алгоритма llama.cpp, а не CacheBlend.

Это явно экспериментальный режим: известен CPU-контрпример неправильного ответа после переноса при другой предыстории. Пройденные GPU-контроли не гарантируют качества произвольных запросов. Само ограничение сдвига занятым диапазоном проверено отдельно и не устраняет эту особенность приблизительного reuse.

## Установка и проверки

- Сначала подготавливается отдельная нативная сборка. Установленные baseline-библиотеки остаются на месте.
- Текущие скрипты, параметры и весь чистый кэш сохраняются в `~/Library/Application Support/radeon-llm/backups/before-experimental-reuse-*`.
- Эксперимент получает новый каталог кэша с отдельным отпечатком аргументов, включая `--cache-reuse 64` и путь сборки. Снимки приблизительного режима не смешиваются с прежним точным кэшем. Первый запрос после смены режима может потребовать холодной обработки.
- Выполняются API/tool-call проверки, перенос с использованием глобального значения по умолчанию без специального поля в запросе, сравнение скорости до/после сдвига и A/B/A + перезапуск/B через индексированный кэш.
- При ошибке установщик пытается вернуть предыдущие профиль, native build и чистый кэш. Новый экспериментальный кэш при откате сохраняется отдельно внутри резервной копии.
- После успешных проверок исходный `server/config.json` также обновляется, чтобы последующие обновления скриптов не отключали режим неожиданно.

OpenCode перенастраивать не нужно: адрес, ключ и alias не меняются. В логах и статусе появляется `EXPERIMENTAL`. Полный вывод установщика сохраняется автоматически.

## Статус и отключение

```bash
./daemon.command status
./cache-status.command
./enable-experimental-reuse.command --rollback
```

Статус показывает `KV reuse: EXPERIMENTAL, min=64 tokens`, режим активного сдвига и параметры индекса. Через API это поля `experimental_chunk_reuse`, `chunk_reuse_min_tokens`, `active_only_shift` в `/cache/status`.

Откат восстанавливает и исходную конфигурацию проекта, и параметры установленного демона. Для отдельного контрольного запроса без переиспользования нужны одновременно `cache_prompt:false` и `n_cache_reuse:0`; одно отключение переноса не делает уже приблизительный кэш точным.

## Проверки перед включением на Radeon

На CPU/2048 через тот же proxy проверен глобальный режим без request-level `n_cache_reuse`: 200 токенов переиспользованы, пересчитан один, генерация до/после 7,07 → 8,13 токена/с. Индекс A/B/A и перезапуск/B, авторизация, streamed tool call и tool result прошли. Проверены отдельный отпечаток кэша, advisory-lock ожидание остановки при запрете PID probe и полный откат native build/конфигурации/снимков.

Отчёты применения: `logs/experimental-reuse-install.json`, `logs/experimental-reuse-daemon-check.json`, `logs/indexed-cache-gpu-check.json`. Последняя консольная сессия: `logs/latest-enable-experimental-reuse.json`.

## Ограничение самостоятельного включения из Codex

Запись файлов была разрешена пользователем, но `launchctl bootout` из процесса Codex вернул `Operation not permitted`. Служба с прежним PID осталась работающей, API готов, профиль exact prefix сохранён. Для включения достаточно запустить `enable-experimental-reuse.command` в обычном Terminal и сообщить об окончании; лог читается агентом самостоятельно.
