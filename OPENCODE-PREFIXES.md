# Предварительный расчёт служебных префиксов OpenCode

Проверено на работающем Radeon 560X, OpenCode 2.1.4 и проекте
`/path/to/project`: префиксы `radeon` — 3297 токенов,
`build` — 5133, `plan` — 5247. Обычный chat с новым вопросом повторно использовал
весь префикс; вычислялись только 9 новых токенов за 1,6–2,1 с нативного prefill.
Повторный прогрев занял 1,93 / 1,22 / 0,91 с соответственно на вызов
`/completion`, включая выбор и восстановление снимка, без последующего ожидания
фонового сохранения. Все три KV-снимка занимают около 1 GiB.
Первый прогрев: `logs/opencode-prefix-first-warmup.json`; повторная проверка:
`logs/opencode-prefix-warmup.json`. 25 тестов Python прошли.

`warm-opencode.command` получает настоящие запросы установленного OpenCode для
`radeon`, `build` и `plan`, выделяет общую часть до пользовательского вопроса и
вычисляет её заранее на работающем Radeon-демоне. Демон сохраняет полученный KV
через существующий SQLite-индекс. Обычные запросы автоматически выбирают подходящий
снимок по точному совпадению токенов; менять OpenCode или переустанавливать демон
не требуется.

Сам индекс KV общий для всех проектов: его ключ не содержит идентификатор проекта,
он строится из совместимости модели/сборки и входных токенов. Поэтому из нового
проекта можно обращаться сразу, без отдельного запуска прогрева: демон уже ищет
совпадающее начало среди всех сохранённых снимков. Каталоги по проектам относятся
к диагностическим токенизированным профилям скрипта, а не к изолированным KV-базам.

Проверка двух разных рабочих папок показала общий префикс 1308 токенов для
`radeon` и 1756 для `build`/`plan`; подходящие снимки уже присутствуют в рабочем
индексе. Результат: `logs/opencode-cross-project-prefix.json`. Полные 3297/5133/5247
токенов не универсальны: путь и сведения об окружении появляются внутри системного
промпта раньше описаний инструментов. Изменение пути обрывает точное совпадение,
даже если текст инструментов дальше одинаков. Чтобы переиспользовать весь этот
объём между произвольными проектами, потребуется изменить порядок формирования
промпта, расположив постоянные инструкции и инструменты перед переменными
сведениями проекта, и отдельно проверить такое изменение. Существующий скрипт
порядок промпта не меняет. Снимки переживают перезапуск, но не закреплены от
очистки по обычной политике кеша.

Запускайте для той папки, в которой будете работать:

```bash
/path/to/radeon-llm/warm-opencode.command /path/to/project --verify
```

Первый расчёт может занимать несколько минут. Следующие запуски используют уже
вычисленные совпадающие префиксы. Ускорение возникает при последующем запросе:
затраты первого расчёта переносятся на прогрев, а не исчезают.

Варианты:

```bash
./warm-opencode.command /path/to/project --agents build plan
./warm-opencode.command /path/to/project --capture-only
./warm-opencode.command /path/to/project --wait 120
```

Без пути используется текущая папка. `--capture-only` получает и токенизирует
префиксы без вычисления на GPU. `--wait` ждёт освобождения демона перед каждым
прогревом; по умолчанию занятый демон не получает новых задач. Проверка занятости
не резервирует сервер: при одновременном поступлении запроса задачи могут встать
в очередь одного слота. Лучше прогревать до начала работы.

## Что входит в префикс

Используются реальные системные инструкции, окружение проекта, описания
инструментов и постоянные сообщения режима (в том числе напоминание Plan).
Приёмник на localhost возвращает OpenCode только текст `OK`, не запрашивая
вызовов инструментов. Используются отдельные временные XDG-каталоги,
`--standalone` и конфигурация проекта `radeon-llm/opencode.json`; основная служба
OpenCode и её история не меняются. Если используется другая конфигурация,
укажите её через `--config`. Глобальные настройки из пользовательского
XDG_CONFIG_HOME в изолированный захват не копируются.

Форматирование выполняет `/apply-template` самого llama-server. Из результата
удаляется вопрос-маркер вместе со всем продолжением. Токены дополнительно
сверяются с полным запросом, чтобы не включить токен, слившийся с началом вопроса
на границе BPE.

Прогрев отправляет `/completion` с `n_predict: 0` и `n_cache_reuse: 0`:
приблизительный перенос фрагментов отключён для этого запроса. Текущая сборка
llama.cpp всё же выбирает один следующий токен из логитов prefill; он не
декодируется обратно в KV и отбрасывается скриптом. Продолжение ответа не
вычисляется. После прогрева проверяется наличие совместимого снимка с точным
идентификатором токенов в индексе. Флаг `--verify` затем проверяет обычные chat
запросы с другим пользовательским текстом, по одному выходному токену на режим,
и требует фактического повторного использования служебного префикса.

## Хранение и обновление

Токенизированные профили: `prefix-profiles/<hash-пути-проекта>/<agent>.json`.
Они содержат служебный контекст проекта, поэтому файлы имеют права 600,
каталог профиля — 700 и исключён из Git. Это входные токены, не сами KV.
KV остаются в установленном демоне, в `cache/kv`, под обычными лимитами:
8 GiB на диске, до 16 вариантов, до 1 GiB горячих отображений, TTL 30 дней.
Снимок с историей может заменить более короткий прогретый префикс — его начало
по-прежнему можно использовать. Снимки могут вытесняться согласно обычной
политике частоты и давности; они не закреплены навсегда.

Прогрев повторяют после смены модели, шаблона, OpenCode, инструментов,
инструкций проекта или его пути. Дата в служебном промпте тоже влияет на точное
совпадение. Скрипт каждый раз получает актуальные запросы, а нативный сервер
проверяет совпадение токенов перед использованием KV.

Этот механизм сохраняет служебную часть. При переключении режима в существующем
диалоге историю после изменившегося префикса приходится пересчитывать. Он также
не увеличивает окно 16k и не уменьшает число токенов, занимаемое инструкциями.

## Логи

Полный вывод автоматически сохраняется в `logs/sessions/warm-opencode-*.log`.
Указатель на последний запуск: `logs/latest-warm-opencode.json`.
Результаты по режимам: `logs/opencode-prefix-warmup.json`, включая число токенов,
время вычисления, размер подтверждённого снимка и проверку chat при `--verify`.
Захваченные служебные запросы для диагностики сохраняются с правами 600 в
`work/opencode-prefixes/last-capture-*.json` вне каталога deliverables.
