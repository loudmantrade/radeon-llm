# Демон с KV-кэшем Q8

Применить профиль и проверить на Radeon из Terminal:

```bash
/path/to/radeon-llm/enable-q8.command
```

Контекст остаётся 8192. Веса модели остаются Q4_K_M. Ключи и значения KV переводятся из F16 в Q8_0. Для значений Q8 включается Flash Attention и используется отдельная FA-only сборка, уже прошедшая полный тест 16k/Q8 на Radeon. Другие обходы ошибок AMD subgroup остаются включены. Ожидаемый размер KV-буфера — 612 МиБ вместо 1152 МиБ. Снижение памяти не гарантирует ускорения первичной обработки.

Установщик сначала подготавливает отдельную нативную сборку, затем останавливает сервис и сохраняет прежние скрипты, конфигурацию и F16-снимок в `~/Library/Application Support/radeon-llm/backups/before-q8-*`. Исходный стабильный нативный runtime сохраняется. Старый F16-снимок не загружается в Q8: первый запрос после перехода будет холодным.

После запуска проверяются фактические параметры по новым строкам лога: Q8 для K/V, контекст 8192, включённый FA, полная выгрузка весов на GPU и отсутствие существенного CPU fallback. Далее выполняются API/tool-call проверки и сохранение/восстановление KV после реального перезапуска. При ошибке этих этапов устанавливается прежний профиль и запускается прежний демон. Если откат сам завершится ошибкой, её вывод останется в Terminal, резервная копия не удаляется.

Отчёты после успешной установки: `logs/q8-daemon-install.json`, `logs/kv-persistence-gpu-check.json`. Прежний F16-отчёт сохранён в `logs/kv-persistence-gpu-check-f16.json`.

Ручной возврат к профилю непосредственно перед последним переходом:

```bash
/path/to/radeon-llm/enable-q8.command --rollback
```

Откат меняет установленный runtime; исходная конфигурация проекта остаётся Q8. Повторное `update-scripts` применит конфигурацию проекта снова. Для обычного включения Q8 используйте именно `enable-q8.command`, чтобы получить резервную копию и проверки.

## Локальная проверка перед установкой

Сборка с Q8 K/V на CPU прошла реальный перезапуск: восстановлены 797 из 798 входных токенов, ответ корректен, prefill 20,72 с → 0,15 с. Снимок 799 токенов занимает 59,7 МиБ против прежних 112,4 МиБ F16. Также проверены несовместимый отпечаток, ошибка новой записи и восстановление прежних конфигурации, бинарников и снимка при откате. Фактическое применение и проверка 8k/Q8 на Radeon выполняются установщиком в Terminal.

## Исправление проверки инициализации

Первый запуск реально включил Q8 K/V, FA и KV 612 МиБ с графом из двух частей, но был отменён из-за отсутствующего маркера. Автоподбор памяти инициализирует GPU с подавлением сообщений и скрывает этот маркер; код common/fit.cpp временно меняет callback логирования. Для фиксированного профиля теперь явно задаётся `--fit off`, как в ранее прошедшем полном эксперименте. Строгая проверка маркера сохраняется. Лог текущего запуска дополнительно записывается в `logs/q8-daemon-startup.log` до проверок и отката.

## Переход с 8k на 16k

Текущая целевая конфигурация проекта — 16384 токена с KV Q8. Установленный демон меняется после `./enable-16k.command`; OpenCode limit и тайм-аут обновляются после проверок. [Инструкция 16k и откат](DAEMON-16K.md).
