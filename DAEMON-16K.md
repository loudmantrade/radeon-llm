# Контекст демона 16k

Применить из обычного Terminal:

```bash
/path/to/radeon-llm/enable-16k.command
```

Целевой профиль: 16384 токена, K/V Q8_0, GPU Flash Attention в ранее проверенной FA-only сборке. KV-буфер — 1224 МиБ. Веса Qwen3-4B Q4_K_M, адрес API и ключ сохраняются. Лимит ответа остаётся 1024 токена; 16k — общая ёмкость входа и генерации.

Установщик сохраняет текущий профиль, нативную сборку, дисковый снимок и конфигурацию OpenCode, запускает 16k, проверяет фактические параметры по логу, API/tool calls и переиспользование кэша после перезапуска. Длинный 10k-тест заново не запускается: тот же профиль модели/сборки/типа KV уже прошёл его ранее. Текущая проверка подтверждает установку и восстановление короткого префикса при ёмкости 16k.

Только после успешных проверок лимит контекста OpenCode меняется на 16384, тайм-аут — минимум на 2400000 мс (40 минут). Открытый OpenCode нужно завершить и запустить заново через `opencode-radeon.command` для загрузки нового лимита. При ошибке проверок установщик пытается вернуть прежний сервер и прежний OpenCode config.

Снимок 8k сохраняется в резервной копии; в 16k он не загружается из-за изменения отпечатка настроек. Первый запрос после перехода холодный. Новый снимок 16k затем автоматически восстанавливается при перезапусках.

В измеренном ранее тесте 16k документ около 10k токенов обрабатывался впервые около 25 минут, а повторный запрос занял около 9 секунд. Увеличение ёмкости не ускоряет первичную обработку. Эти времена относятся к тому тесту и не предсказывают точно скорость каждого запроса OpenCode.

Проверенная ёмкость для Radeon 4 ГБ — 16k/Q8. Для 32k тот же KV занимает около 2448 МиБ, а веса около 2376 МиБ, то есть их сумма уже превышает 4 ГБ без учёта рабочих буферов. Переход выше 16k потребует отдельного выбора формата кэша или размещения части вычислений в RAM.

Откат к профилю перед последним применением:

```bash
/path/to/radeon-llm/enable-16k.command --rollback
```

Откат меняет установленный профиль и OpenCode config; исходный `server/config.json` остаётся целевым профилем 16k. Отчёты успешного применения: `logs/q8-daemon-install.json` и `logs/kv-persistence-gpu-check.json` (поле context должно быть 16384).
